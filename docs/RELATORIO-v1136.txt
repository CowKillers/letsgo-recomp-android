PROBLEMA 1: Imagem do jogo girada 90° e deformada
-----------------------------------------------
CAUSA:
- create_swapchain() forçava imageExtent para 1280x720, ignorando
  currentExtent da superfície.
- vk_frame_begin() comparava tamanho da janela com swapchain a cada
  frame, causando recriações repetidas.
- present.vert não compensava rotações de 90/180/270° do preTransform.

EVIDÊNCIA:
- Screenshots mostravam conteúdo 3D girado 90° enquanto UI 2D estava normal.
- Log mostrava swapchain 1920x1080 mas jogo renderizando 720x1280.

SOLUÇÃO:
- device.c create_swapchain(): removido extent fixo. Respeita currentExtent
  quando definido; quando variável, usa tamanho da janela limitado aos
  intervalos suportados (min/maxImageExtent).
- device.c: adicionados logs de currentExtent, currentTransform,
  supportedTransforms, imageExtent e preTransform escolhidos.
- vk.h: adicionado campo sc_rotation ao VkG.
- device.c create_swapchain(): mapeia currentTransform para rotação
  (0/90/180/270°) em g_vk.sc_rotation.
- shaders.c present.vert: adicionada compensação de rotação via
  pc.a.y (0=0°, 1=90°, 2=180°, 3=270°), aplicada aos UVs.
- device.c vk_frame_begin(): recriação só quando tamanho da janela
  realmente muda (last_w/last_h), com contador e log do motivo.

VALIDAÇÃO:
- Build compila sem erros (SMOKE_OK).
- Validação visual em aparelho: PENDENTE.

PROBLEMA 2: Textos ausentes nas caixas de diálogo
------------------------------------------------
CAUSA:
- nvnTextureFlushTexels() estava vazio em runtime/nvn/objects.c.
  O jogo atualiza o atlas de glifos na CPU e chama FlushTexels para
  notificar a GPU, mas a notificação era ignorada. A GPU exibia
  textura desatualizada (vazia).

EVIDÊNCIA:
- Log confirmava fonte carregada (/system/fonts/Roboto-Regular.ttf).
- Idioma correto (en-US). Caixas de diálogo vazias mesmo assim.
- nvnTextureFlushTexels = { (void)c; } — nenhuma operação.

SOLUÇÃO:
- objects.c nvnTextureFlushTexels(): implementado de verdade.
  Obtém NvnTexture via HOST(), calcula tamanho via tegra_total_size(),
  chama backend_pool_written(addr, size) para marcar a região como
  suja. Integra ao mecanismo existente de dirty-tracking (não é
  invalidação global).
- objects.c nvnTextureInvalidateTexels(): mesmo tratamento.

VALIDAÇÃO:
- Build compila sem erros.
- Validação visual (letras visíveis em diálogos): PENDENTE — requer
  teste em aparelho.

PROBLEMA 4: Build não falhava em erros de compilação paralela
--------------------------------------------------------------
CAUSA:
- build-runtime.sh usava variável `fail` modificada em subshells
  (jobs com &). Variável de subshell não afeta o pai.

SOLUÇÃO:
- Substituído por arquivo marcador $OBJDIR/.build_failed.
- Jobs tocam o arquivo em caso de erro; verificação final usa
  [ -f $FAILFILE ] e sai com exit 1.
